# OctoAcme — Cross-Functional Roles Integration Checklist

## Purpose
Ensure all necessary roles are identified, engaged, and integrated throughout the project lifecycle based on project scope and complexity.

## When to Use
- During project initiation to identify who should be involved
- During sprint or milestone planning to confirm role participation
- During retrospectives to evaluate cross-functional collaboration

## Project Phases & Role Involvement

### Initiation Phase
Identify and confirm involvement:

- [ ] **Project Manager** — assigned and leading coordination
- [ ] **Product Manager** — defining problem statement and success metrics
- [ ] **Product Lead/Sponsor** — providing stakeholder alignment
- [ ] **Scrum Master** — confirmed (if using agile approach)
- [ ] **UX Designer** — engaged for discovery and research needs assessment
- [ ] **Customer Success Manager** — consulted for customer insights and launch planning
- [ ] **Key Developers** — included in feasibility discussions
- [ ] **QA Lead** — participating in requirements clarification

### Planning Phase
Expand team and clarify responsibilities:

- [ ] **UX Designer** — leading or supporting discovery/research activities
- [ ] **Technical Writer** — informed of scope; planning documentation approach
- [ ] **Developers** — breaking down work and identifying blockers
- [ ] **QA Lead** — defining test strategy and acceptance criteria
- [ ] **Customer Success Manager** — providing user personas and adoption strategy input
- [ ] **Scrum Master** — facilitating planning ceremonies and establishing team norms

### Execution Phase
Ensure ongoing collaboration:

- [ ] **Developers** — implementing and coordinating on design feasibility with UX
- [ ] **UX Designer** — conducting design reviews and usability testing
- [ ] **QA/Testing** — running tests aligned with acceptance criteria
- [ ] **Technical Writer** — drafting user documentation alongside feature development
- [ ] **Scrum Master** — facilitating standups and removing blockers daily
- [ ] **Customer Success Manager** — gathering early feedback from pilot users (if applicable)
- [ ] **Project Manager** — tracking progress and escalating risks

### Release Phase
Prepare for go-live:

- [ ] **Technical Writer** — finalizing documentation and release notes
- [ ] **QA/Testing** — executing pre-release smoke tests
- [ ] **Customer Success Manager** — preparing launch communication and user training
- [ ] **Developers** — standing by for hotfixes
- [ ] **Project Manager** — managing deployment schedule and communication
- [ ] **Scrum Master** — coordinating team availability and post-launch support plan

### Post-Launch Phase
Ensure transition and learning:

- [ ] **Customer Success Manager** — monitoring user adoption and gathering feedback
- [ ] **Technical Writer** — updating documentation based on real usage
- [ ] **QA/Testing** — monitoring for post-launch issues
- [ ] **Developers** — addressing bugs and quick wins
- [ ] **Product Manager** — analyzing success metrics and impact
- [ ] **Scrum Master** — leading retrospective
- [ ] **Project Manager** — capturing lessons learned and closure activities

## Role Interaction Quick Reference

**Developer + UX Designer:**
- Confirm feasibility of designs during design reviews
- Establish shared acceptance criteria for UX quality

**Developer + Technical Writer:**
- Document API/technical specs alongside implementation
- Validate code examples in documentation

**QA + UX Designer:**
- Test for both functional correctness and usability
- Create test cases that include UX acceptance criteria

**Customer Success Manager + Product Manager:**
- Align on launch communication and user training
- Plan post-launch feedback loops for product roadmap input

**Scrum Master + Project Manager:**
- Coordinate sprint execution with project timeline
- Escalate impediments collaboratively

**All roles + Product Manager:**
- Align regularly on backlog priorities and acceptance criteria
- Validate that work aligns with product goals

## Red Flags for Missing Role Involvement

- ⚠️ **UX concerns arise late** → UX Designer should have been engaged earlier
- ⚠️ **Documentation incomplete at release** → Technical Writer should have been included in planning
- ⚠️ **Poor user adoption post-launch** → Customer Success Manager input was missing
- ⚠️ **Frequent scope changes** → Product Manager clarity needed; backlog not well-managed
- ⚠️ **Team morale or process issues** → Scrum Master coaching needed
- ⚠️ **Customer feedback ignored** → Communication loop between Customer Success and Product/Dev missing

## How to Adapt This Checklist

- **Small/simple projects:** Focus on core roles (PM, PdM, Developer, QA). Bring in supporting roles as needed.
- **Complex/large projects:** Assign dedicated owners for each role. Plan explicit handoffs between phases.
- **Distributed teams:** Establish clear communication channels and asynchronous review processes for each role.
- **Evolving teams:** Use this checklist during onboarding to clarify role expectations and interactions.

## Sample Role Allocation by Project Size

### Small Feature (< 2 weeks)
- Project Coordinator: PM (part-time)
- Product Definition: PdM
- Development: 1–2 Developers
- Testing: Embedded in Dev or light QA
- UX: If UI changes, minimal UX review
- Technical Writing: Release notes only

### Medium Project (2–6 weeks)
- Project Manager: dedicated
- Product Manager: dedicated
- Development: 3–5 Developers
- QA: 1–2 dedicated QA engineers
- UX Designer: dedicated for design work
- Scrum Master: facilitating ceremonies
- Technical Writer: documentation
- Customer Success: advisory input

### Large Initiative (6+ weeks)
- All roles fully engaged
- Customer Success Manager: active user feedback loops
- Technical Writer: extensive documentation
- UX Designer: research, design systems, usability testing
- Dedicated Scrum Master: team coaching
- Project Manager: stakeholder coordination
- Potential: sub-teams with their own leads
